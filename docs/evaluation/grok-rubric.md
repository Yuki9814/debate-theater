# Grok Build Evaluation Rubric: 论衡剧场 AI 辩论 Web App 重构验收评分标准

**版本**：v1.0  
**适用范围**：Next.js + TypeScript 重构完成后整体验收  
**通过线**：总分 >= 90 分  
**低于 90 分处理**：必须返工至达标后方可进入公开发布与商业化阶段  
**评审原则**：客观、可量化、可验证；前端体验部分即使暂由 Gemini CLI / Grok Build 负责，仍需按本标准一次性验收通过。

## 各维度详细验收要点

### 1. 商业化/盈利闭环 - 15 分

- 存在至少一种可立即落地的盈利模式：订阅制、辩论次数包、高级模型付费或企业定制，并已在 UI 中可见入口（3 分）。
- 已完成 Stripe、微信支付、支付宝等至少一种支付渠道的沙盒集成，测试支付流程完整可走通（4 分）。
- 用户可清晰看到免费额度与付费升级对比，转化路径不超过 3 次点击（3 分）。
- 具备基础收入追踪与成本对账能力：简单仪表盘或可导出 CSV（2 分）。
- 定价策略有明确文档说明，包含套餐权益和取消订阅规则（3 分）。

### 2. 产品定位与价值主张 - 8 分

- 首页与产品页明确写出「论衡剧场」与普通 AI 聊天/辩论工具的差异：结构化、评判、存档、可复盘（3 分）。
- 目标用户画像与核心使用场景已文档化并体现在 UI 文案中（2 分）。
- 竞品差异化亮点有清晰呈现，例如多 Provider 切换、实时打分、辩论剧本导出（2 分）。
- 品牌调性统一，中文正式且具思辨感，无低俗营销话术（1 分）。

### 3. 前端用户体验 - 12 分

- 辩论流程主路径：创建、选题、选正反方、多轮辩论、AI 评判、保存，在桌面与移动端均不超过 8 次点击完成（3 分）。
- 响应式良好，移动端无横向滚动、按钮可点击、字体可读（2 分）。
- 加载状态、错误状态、空状态完整且友好（2 分）。
- 辩论界面交互细节优秀：打字机效果、滚动跟随、角色头像区分、键盘快捷键支持（3 分）。
- 无明显性能问题：首屏小于 2.5s，切换 Provider 响应小于 800ms（2 分）。

### 4. AI 辩论核心功能与体验 - 15 分

- 支持完整结构化辩论流程：立论、质询、反驳、结辩、第三方评判，且包含分数与理由（5 分）。
- 支持多 Provider 实时切换，切换后历史记录仍可用（3 分）。
- 评判维度可配置，并能生成结构化 JSON 便于后续分析（3 分）。
- 辩论可暂停、继续、导出，单场辩论时长与轮次可配置（2 分）。
- AI 回复不跑题，能针对上文有效反驳，评判有理有据（2 分）。

### 5. Provider / API Key 安全 - 10 分

- 所有 API Key 仅存储在服务端，前端绝不暴露（5 分，一票否决项）。
- 支持用户自带 Key 与平台统一 Key 模式，两种模式均安全隔离（2 分）。
- Key 轮换、权限最小化、调用审计日志已实现（2 分）。
- 错误提示不泄露 Key 片段或 Provider 内部错误细节（1 分）。

### 6. 数据持久化与用户数据 - 8 分

- 辩论记录、用户偏好、历史对战完整持久化，支持按时间、主题、胜率检索（3 分）。
- 用户登录后可跨设备同步数据（2 分）。
- 支持辩论数据导出与删除（2 分）。
- 数据模型设计合理，无明显冗余或性能隐患（1 分）。

### 7. 支付与订阅系统准备 - 10 分

- 订阅状态实时同步：激活、取消、过期、续费提醒（3 分）。
- 已实现 webhook 处理支付成功、失败、退款场景（3 分）。
- 发票、账单历史、订阅管理后台页面已就位（2 分）。
- 定价与权益在代码与文案中一致，无“假订阅”占位（2 分）。

### 8. 成本控制与可扩展性 - 7 分

- 具备 AI 调用成本实时监控与每日/月度预算告警机制（2 分）。
- 实现用户级与全局级限流、缓存策略、流式响应优化（2 分）。
- 架构支持水平扩展：无状态服务、数据库连接池、队列（2 分）。
- 已记录各 Provider 每 1K token 成本并在后台可见（1 分）。

### 9. 安全合规与隐私保护 - 8 分

- 内容安全过滤已上线且可配置（3 分）。
- 隐私政策、服务条款、用户协议完整且可访问（2 分）。
- 用户数据加密存储、访问控制、审计日志（2 分）。
- 无已知 OWASP Top 10 高危漏洞（1 分）。

### 10. 测试、CI/CD、发布运维 - 7 分

- 单元测试、集成测试、E2E 关键路径覆盖率 >= 70%，辩论主流程必须覆盖（2 分）。
- CI/CD 流水线完整：lint、type check、build、test、部署，失败自动阻断（2 分）。
- 生产环境监控接入：错误率、延迟、AI 调用成功率、成本（2 分）。
- 支持灰度发布/回滚，文档齐全（1 分）。

## 一票否决项

满足任一项即直接判定不通过：

1. 任何 API Key 以明文、环境变量泄露、localStorage、客户端 JS 变量等方式暴露给浏览器。
2. 无法完成一次完整结构化 AI 辩论流程。
3. 完全没有可落地盈利路径：支付集成缺失、订阅状态无法管理或仅展示“敬请期待”。
4. 无用户认证或数据持久化，刷新后辩论记录全部丢失。
5. 存在可被利用的严重安全漏洞，如未授权访问用户数据、SQL 注入、XSS 任意脚本、任意文件上传。
6. 生产环境部署后，核心辩论路径 5xx 错误率持续大于 3%，或单次 AI 调用平均耗时大于 15s 且无优化计划。
7. 缺少内容安全过滤，导致可轻松生成违法、色情、暴力、仇恨内容且无任何拦截。
8. 缺少最基本的隐私政策与服务条款，或用户数据被用于训练模型而未明确告知。

## 说明

本标准为重构前置评审基准。所有验收要点均需提供可演示、可截图、可测试的证据。前端实现虽后续由 Gemini CLI 与 Grok Build 负责，但必须一次性通过前端体验与 AI 核心功能相关要点，否则视为重构未完成。
