# Gemini CLI Evaluation Rubric: 「论衡剧场 / Debate Theater」商业级重构验收评分标准

根据项目“可发布、可盈利”的商业化重构目标，Gemini CLI 制定以下 100 分制验收标准。最终重构交付物必须达到 **90 分及以上** 并无任何“一票否决项”方可视为通过。

## 总分表

| 评估维度 | 分值权重 | 核心关注点 |
| :--- | :---: | :--- |
| 商业化与盈利闭环 | 15 分 | 商业模式可行性、付费转化路径、计费逻辑抽象、支付网关准备 |
| 产品定位与前端体验 | 15 分 | 目标用户契合度、响应式设计、沉浸式交互、首屏性能 |
| AI 辩论核心体验 | 20 分 | 辩论引擎稳定性、上下文与角色管理、流式输出、裁判裁决逻辑 |
| Provider 与 API Key 安全 | 15 分 | 密钥加密与防泄露、服务端代理请求、接口鉴权与防盗刷 |
| 数据持久化与状态管理 | 10 分 | Prisma Schema 设计、会话无缝恢复、数据一致性保障 |
| 成本控制与资源优化 | 10 分 | Token 消耗管理、上下文截断/压缩算法、并发与无效请求拦截 |
| 安全合规、测试与运维 | 15 分 | 核心自动化测试覆盖、CI/CD 构建流水线、Prompt 注入防御 |
| 总计 | 100 分 | 通过线：>= 90 分 |

## 每项验收要点

### 1. 商业化与盈利闭环（含支付/订阅准备）- 15 分

- 计费网关抽象（5 分）：后端是否设计高内聚 Billing Service 或中间件，为 Stripe、微信支付、支付宝预留标准钩子，支持点数扣除或订阅鉴权。
- 转化漏斗与付费墙设计（5 分）：免费试用额度是否清晰；触发付费墙时，交互是否平滑且具备转化力。
- 双轨商业模式支持（5 分）：架构是否支持 BYOK 与 SaaS 代扣代缴双轨并行。

### 2. 产品定位与前端体验 - 15 分

- 视觉与沉浸式 UI（5 分）：UI/UX 是否契合“剧场与辩论”的氛围；动效过渡自然。
- 响应式多端适配（5 分）：移动端、平板、桌面端均不可出现溢出或遮挡。
- 加载性能与 RSC（5 分）：利用 Next.js App Router 与 React Server Components 减少客户端 JS，核心页面首屏加载目标小于 1.5s。

### 3. AI 辩论核心体验 - 20 分

- 辩论引擎状态机与流式输出（8 分）：多 AI 角色交替发言调度严密，全链路支持 SSE 流式打字机效果，并允许用户随时中止生成。
- 角色一致性与 Prompt 工程（6 分）：系统预设健壮，辩手立场、语气、逻辑深度多轮保持一致。
- 裁判总结与复盘机制（6 分）：Judge 模块能精准提取论点，并按逻辑性、论据有效性等维度给出胜负裁决与全局复盘。

### 4. Provider 与 API Key 安全 - 15 分

- 密钥加密与隐匿（8 分）：用户 BYOK API Key 必须加密存储，严禁明文写入前端、数据库明文字段或日志。
- 代理请求与限流防御（7 分）：所有模型请求必须通过 Next.js API Routes 服务端发起，禁止前端直连模型接口；服务端必须限流防刷。

### 5. 数据持久化与状态维护 - 10 分

- 健壮的数据模型（5 分）：Prisma Schema 清晰解耦 User、Session、Round、Message、ProviderConfig，具备查询性能和扩展性。
- 断线/刷新恢复（5 分）：辩论中刷新、断网或关闭重开后，系统能通过数据库和本地缓存恢复，历史对话不丢失。

### 6. 成本控制与资源优化 - 10 分

- Token 精度管理与上下文截断（6 分）：长会话具备滑动窗口或 Summary-based Memory 策略，防止 Token 费用暴增。
- 冗余请求拦截（4 分）：拦截重复请求，提供长度校验和基础预检，减少无效模型调用。

### 7. 安全合规、测试与运维发布 - 15 分

- 测试覆盖率（6 分）：辩论流调度、计费钩子、状态机转换等核心引擎必须有单元测试；核心路径建议具备 Playwright/Cypress E2E。
- CI/CD 与环境治理（5 分）：Vercel 构建部署顺畅，开发/测试/生产环境变量隔离清晰，构建脚本健壮。
- 安全与反注入（4 分）：防范 XSS、CSRF；对主题和自定义 Prompt 做基础清洗，防 Prompt Injection。

## 一票否决项

触发任一项即打回，不可发布：

1. 密钥或 Token 暴露：前端直连外部模型 API，平台 Key 暴露，或用户 API Key 明文记录。
2. 计费防线被击穿：用户可通过抓包、篡改前端参数或 localStorage 绕过付费墙。
3. 未实现流式输出与阻塞控制：AI 发言长时间等待后一次性展示，严重偏离现代 AI 产品体验。
4. 状态机死锁或数据错乱：高频操作后前后端会话状态脱节、白屏、无限 Loading 或跨用户串号。
5. 工程构建失败：`pnpm install` 与 `pnpm build` 不能正常完成。
